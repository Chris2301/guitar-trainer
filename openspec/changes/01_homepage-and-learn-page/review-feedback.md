## Engineer Assessment
### Overall Decision: REFACTOR
### Reasoning per finding

#### architect-reviewer — Placeholder template in app.html
- **Decision**: Fix
- **Reasoning**: This is the most clear-cut finding. The entire 341-line placeholder template is autogenerated Angular CLI content that has zero value in the application. It actively harms readability, bloats the DOM, and will break the moment real content is added. Replacing with just `<router-outlet />` is trivial and removes a large amount of noise. Multiple reviewers flagged this (codestyle-Medium, performance-Medium, architect-Critical) which confirms it is a real issue.

#### architect-reviewer — Empty routes array
- **Decision**: Accept (no fix now)
- **Reasoning**: Task 1.1 is explicitly scoped as "Angular v21 project genereren met standalone components en SCSS". The routes for `/` and `/learn` belong to later tasks that create the actual page components. Adding route definitions without the components they point to would be dead code. The empty routes array is the correct state for a freshly scaffolded project. This is a false positive in the context of task 1.1.

#### codestyle-reviewer — Class named App instead of AppComponent
- **Decision**: Fix
- **Reasoning**: This is a real deviation from Angular convention. While Angular v21 CLI now generates `App` by default (dropping the `Component` suffix), the project instructions say to follow Angular conventions and the broader Angular ecosystem still predominantly uses the `Component` suffix. More importantly, as the codebase grows, having `AppComponent` makes it immediately distinguishable from non-component classes. The rename is mechanical and low-risk.

#### architect-reviewer — Tests for placeholder content will break
- **Decision**: Fix
- **Reasoning**: Since we are removing the placeholder template, the test that checks for `'Hello, guitar-trainer'` will fail. The test must be updated to verify meaningful behavior -- presence of `<router-outlet>` and component creation. This is a direct consequence of the template fix.

#### architect-reviewer — Test runner mismatch (vitest + Jasmine-style TestBed)
- **Decision**: Accept (no fix now)
- **Reasoning**: Angular v21 with `@angular/build:unit-test` builder officially supports vitest as its test runner. The `TestBed` API is Angular's own testing utility and is test-runner-agnostic -- it works with vitest just as it does with Jasmine or Jest. The `tsconfig.spec.json` already includes `"types": ["vitest/globals"]`. This setup is the Angular v21 default and is not a mismatch. This is a false positive.

#### architect-reviewer — Missing Cloudflare Pages SPA fallback
- **Decision**: Defer
- **Reasoning**: Deployment configuration (Cloudflare Pages `_redirects`) is infrastructure concern, not project scaffold. There is no mention of Cloudflare Pages in the task description or project.md. Adding deployment-specific files at this stage is premature -- the deployment target may change. This should be handled when deployment is configured.

#### performance-reviewer — Missing ChangeDetectionStrategy.OnPush
- **Decision**: Fix
- **Reasoning**: Adding `OnPush` to the root component is a one-line change that establishes the right pattern from day one. Every component generated after this should use `OnPush`, and having it on the root component sets the standard. The component uses signals which are fully compatible with `OnPush`. No downside.

#### security-reviewer — Missing CSP header
- **Decision**: Defer
- **Reasoning**: CSP configuration depends on knowing which external resources the app will load (Taiga UI CDN fonts, API endpoints, etc.). Adding a restrictive CSP now will likely need to be loosened repeatedly as dependencies are added in tasks 1.2-1.5. Better to add CSP once the dependency picture is clear. This is a real concern but premature for task 1.1.

#### security-reviewer — Missing security headers (X-Content-Type-Options, Referrer-Policy)
- **Decision**: Defer
- **Reasoning**: Same reasoning as CSP. These headers are typically configured at the server/CDN level, not in HTML meta tags. The deployment target is not yet defined. Defer to deployment configuration task.

#### security-reviewer — target="_blank" links missing rel="noreferrer"
- **Decision**: Accept (moot)
- **Reasoning**: The entire placeholder template is being removed, so all these links disappear. No action needed.

#### architect-reviewer — title signal is placeholder dead code
- **Decision**: Fix
- **Reasoning**: Directly resolved by the template cleanup. The `title` signal exists only to serve the placeholder template. When the template is replaced with `<router-outlet />`, the signal becomes dead code and should be removed per project instructions ("No dead code or unused imports").

#### architect-reviewer — No explicit outputPath in angular.json
- **Decision**: Defer
- **Reasoning**: Angular CLI has sensible defaults for `outputPath` (`dist/<project-name>`). Adding an explicit path is only valuable when configuring deployment, which is not in scope for task 1.1.

#### performance-reviewer — Inline styles in template instead of app.scss
- **Decision**: Accept (moot)
- **Reasoning**: Resolved by removing the placeholder template entirely.

#### performance-reviewer — Placeholder DOM nodes on every route
- **Decision**: Accept (moot)
- **Reasoning**: Resolved by removing the placeholder template entirely.

#### Low-severity / Nitpick findings
- **codestyle: signal naming and access modifier** -- Moot after removing the `title` signal entirely as part of template cleanup.
- **security: bootstrap error logging** -- The single `console.error` in `main.ts` is standard Angular CLI output and acceptable for a scaffold. Production logging strategy can be addressed later.
- **security: unpinned dependency versions** -- The `^` ranges are Angular CLI defaults. A `package-lock.json` should already exist (generated by `npm install`) which pins exact versions in practice. No action needed.
- **performance: no lazy-loading in router** -- The routes array is empty; lazy-loading will be configured when routes are added in later tasks.
- **performance: bundle budget too generous** -- The 500kB warning / 1MB error is the Angular CLI default and reasonable for a project that will include Taiga UI. Tightening prematurely may cause false build failures. Defer.
- **architect: lang="en" hardcoded** -- Acknowledged by the reviewer as "no action now". Will be handled in task 1.4 (i18n).
